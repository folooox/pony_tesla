## 测试发现并修复的问题

1. **登录按钮被错误拒绝**：网页统一使用 `no-referrer` 会让 Chromium 的表单 POST 发送 `Origin: null`，导致来源校验拒绝正常登录。首页改为 `same-origin`，OAuth 回调仍保持 `no-referrer`。完整浏览器授权和取消后重试均已通过。
2. **旧车辆选择残留**：刷新列表失败后仍可点击读取旧车辆。现于刷新开始时清空选择并禁用读取；重新获取成功后恢复。
3. **异常数据被误判成功**：无效令牌类型、畸形车辆条目和数组形式车况可能被接受。现在检查响应结构，拒绝无效数据且保留已有有效授权。
4. **无效请求触发内部异常并占用冷却**：`null` 等请求现在返回可理解的 400 错误，并在有效请求前不占用冷却。
5. **中文请求体大小计算错误**：限制改按 UTF-8 字节数计算，过大请求返回可读取的 413 JSON。
6. **慢请求体导致并发检查失效**：读取完请求体后再次检查互斥与冷却，重叠的流式请求只允许一次车况读取。
7. **端口配置缺少校验**：非法端口在启动配置检查时明确拒绝。

## 覆盖的主要流程

- 应用未配置时提示缺失项目并禁用入口；页面和敏感路径要求认证。
- 浏览器发起授权、跨站跳转、回调 Cookie、单次 state、取消和重新授权。
- 加密令牌持久化、重新打开存储、篡改检测、轮换刷新、并发刷新和失败后的恢复。
- 车辆列表、无车辆账号、车辆不属于当前账号、有效单次车况、空车况和异常格式。
- 车辆休眠时不会发起唤醒或实时车况读取。
- 无效来源、错误后台账号、超大/无效请求体、重复及并发读取。
- Tesla HTTP 401/403/408/429/500/503、网络失败、非 JSON 响应，不向浏览器泄露上游响应内容。
- HTTPS、跳转、公钥一致性、页面资源、私有路径保护，以及部署重启后可用性。

浏览器测试的 OAuth 使用本地 HTTPS 模拟服务器，并用只允许测试目标的代理覆盖重定向。Fleet API 响应由测试传输层提供。测试密钥、令牌、VIN 和车况都是合成数据，未写入运行服务的授权存储。

## 复现

需要 Node.js 24.5+、OpenSSL；浏览器依赖安装一次：

```sh
npm ci
npx playwright install --with-deps chromium
npm test
npm run test:browser
```

只读线上验收需要仓库 `.env` 中的公开域名与后台密码：

```sh
npm run test:deployment
npm run test:live-browser
```

线上验收不会点击 Tesla 授权、读取真实车辆或发送控车命令。浏览器模拟截图输出至被 Git 忽略的 `artifacts/test-results/`。测试由上述命令按需运行；没有启动无限循环或周期性车辆轮询。
