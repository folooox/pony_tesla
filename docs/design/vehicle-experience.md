# Pony 车辆体验与 3D 制作基线

2026-10-17。依据现有原生工程及本轮用户要求。本文明确区分设计目标与已完成实现。

## 产品方向

保留 SwiftUI、系统字体、原生 Liquid Glass 和现有四个导航入口。第一款深度适配车型仍为国产 2022 款 Model 3，非焕新版。先把真实车辆做好，再增加完整的 IP 载具体验。

Pony 的辨识度来自安静的车辆展示空间：雾银车漆、石墨座舱、柔和冷灰背景、克制的光照。文字与控件服从系统深浅色和字号；玻璃材质集中在操作层，车身与内饰保持物理材质。行程与充电沿用相同的信息层级、间距和状态语义，不把所有内容做成发光面板。

首页顺序：车辆名与操作菜单 → 演示／连接提示 → 锁车状态 → 车辆及外观／座舱视角 → 电量与续航 → 高频快捷操作 → 空调与位置入口。优先让一屏看懂车辆状态并触达快捷控制。模型旋转只改变查看角度，不能触发控车。空调页从座舱开始，座椅加热和车内状态使用同一个车辆快照。

## 本轮实际实现

- 原生 RealityKit 非 AR 展示，不请求相机权限。
- 程序化轿车交互样机：独立车门、舱盖、车窗、充电口，轮毂、木色仪表台饰条、中控屏、五座座舱。
- 外观与座舱切换、拖动旋转、复位及辅助功能旋转操作。
- 模拟车况回报驱动车身；前后备箱及车窗快捷操作有对应状态；五座加热和方向盘加热可分别演示。
- 减少动态效果、前后台及页面可见性控制气流动画。离线和过期数据不播放持续气流。
- “车况演示”单独注入开合传感器状态，不把手动车门和前备箱关闭伪装成真实远程指令。

**尚未达到官方模型的精度。** 当前几何用来验证相机、节点、状态与界面，未使用官方 3D 资产。没有经过实车尺寸、曲面、缝隙和材质验收。IP 模型、正式资产加载管线、真实 Tesla 命令与遥测均不属于本轮已完成项。

## 官方对标验收

采用同一车型、同一视角、相近显示尺寸和光照进行对比；不能以“能转动”代替“像原车”。正式美术验收前，需要目标官方 App 版本的外观、开门、前后备箱和空调座舱参考；本轮核对的是官方功能文档，尚未完成逐屏视觉比对。

| 项目 | 达标条件 |
| --- | --- |
| 轮廓 | 2022 款前脸、车顶弧线、轴距比例、尾部和轮拱准确；不混入焕新版灯组 |
| 车漆 | 连续清晰的曲面高光，合理金属度与粗糙度；不能靠强泛光掩盖形体 |
| 玻璃 | 挡风玻璃、天幕与侧窗区分；移动端透明排序正确，不遮错内饰 |
| 细节 | 独立门缝、把手、后视镜、灯组、B 柱、充电口与轮毂 |
| 内饰 | 2022 仪表台木饰条、正确方向盘与屏幕、中央扶手、前后排及门板；开门后可见实体内侧 |
| 机构 | 四门各自真实铰点；前备箱、后备箱分别绑定；开盖看到内腔，不暴露实心封顶 |
| 状态 | 开合与车锁独立；未知、离线和旧状态可辨识；各座椅独立加热 |
| 连续交互 | 外观和座舱共用状态，切页、旋转、主题切换不能重置车况 |

模型制作要求见 [3D 资产规范](model-asset-contract.md)。高精度资产是当前最大的交付缺口，需要取得可使用的现成资产或专门建模。不要从静态概念图推断已经具备可用 3D 模型。

## 动效与反馈

以下为设计基线，具体时长需真机调校：

- 车门／舱盖运动 500–750 ms，铰点固定，避免夸张弹跳；回报只有开／关时，角度仅是可读的示意，不表示真实角度。
- 外观到座舱 450–600 ms，相机引导到座椅；座舱模式隐藏外壳属于查看方式，不表示车顶打开。
- 加热用座面、靠背的局部暖色与文字挡位；不把整车变红。座椅通风仅在硬件支持时出现，2022 基线不提供。
- 空调用细小流线表现方向；制热、制冷、除霜分别设计，不用随机烟雾遮挡座舱。本轮先实现通风示意，未模拟真实风向和热场。
- 每次交互立即显示等待反馈，持久状态以服务回报为准。高频加热设置成功后更新控件并写操作记录，避免连续成功弹窗。
- Reduce Motion 保留静态状态标识；VoiceOver 能通过文字获取车门与加热信息，不依赖颜色或 3D 热点。

## IP 深度适配

主题包最终包含：外部模型、内部场景、材质、灯光、相机、状态节点映射、动效与可选声音。原生导航、操作名称、真实车辆状态和错误语义共用，不因主题改变业务能力。

| 主题 | 外观与座舱 | 状态表现 | 无法一一对应的部分 |
| --- | --- | --- | --- |
| Model 3 | 真实车辆、真实五座内饰 | 门与舱盖按结构开合；座椅局部加热；车内气流 | 作为完整物理基准 |
| 塔迪斯 | 警亭外部、开门后的控制室空间；警亭蓝、暖色控制台、克制的顶灯呼吸 | 解锁改变门锁反馈；空调用控制室气流／能量环；充电可驱动中央装置光效 | 两扇警亭门无法表示四扇车门及两个行李箱；保留带明确文字的实车状态层和五座控制，不能把不同打开状态合并成一扇门 |
| 光轮 | 黑色车体、发光轮环、低机位、骑乘舱视角；发光线条属于模型材质 | 充电用轮环能量进度，空调用克制的气流轨迹 | 摩托车没有四门、前后备箱与五座；这些操作进入明确的实车控制层，不在摩托上凭空增加假门或遗漏座位 |

主题的情绪化动画只能由已知状态驱动，不能把解锁、充电、哨兵等状态统统表现为同一种闪光。切主题不发车辆指令、不改变数据新鲜度、不播放默认声音。下载失败保留现有主题。正式分发前记录各模型、纹理和音效的来源与使用范围。

## 后续里程碑

1. **交互样机（本轮）**：原生 3D、独立状态、座舱与模拟控制，建立可替换的节点基线。
2. **官方质感车辆**：确定黑／白内饰与轮毂配置；导入精细模型；修正轮廓、内腔、透明材质与灯光；完成同角度视觉验收。
3. **完整状态效果**：灯光、充电、冷暖气流、除霜、局部加热；补齐失败、过期、未知和减少动态效果的视觉回归。
4. **塔迪斯主题**：先完成一个完整主题，验证非车辆结构与实车状态共存，再扩展光轮。
5. **真车与性能**：通过既有 VehicleService / AppStore 接口接入经验证的能力；检测真机帧率、温升、内存和后台资源释放。
