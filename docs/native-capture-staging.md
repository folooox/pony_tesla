# Native capture — local phase-C foundation (not a receiver)

`backend/native-capture.mjs` is an isolated Node `node:sqlite` journal and materialized trip/charging store. It never opens a socket, fetches Tesla, wakes a vehicle, accepts public uploads, reads credentials, or changes the legacy `history.mjs` database. No package dependencies were added. Keep collection OFF until the genuine receiver/authentication/ownership dispatcher is integrated. Synthetic tests are not Tesla collection acceptance.

## Trusted integration contract / exact API

```js
const store = new NativeCaptureStore(privateNewSQLitePath, {
  clock: Date.now,
  allowSimulation: false, // production/default; use a physically separate fixture DB for simulation
  authenticateAccount(context, vin) { /* fresh native session + current VIN membership; return stable account ID or null */ },
  authorizeOperator(context) { /* trusted operator capability, return exactly true or deny */ },
  authenticateReceiver(context) { /* authenticated upstream transport identity; return {vin, stream} or null */ }
});
```

All validators are **synchronous, injected, trusted seams**, default-deny. They must inspect trusted in-process capabilities or real authenticated session/transport state, never self-asserted request JSON, user headers, `verified: true`, or native-client telemetry. `authenticateAccount` is called on every user operation with the selected VIN; the parent router must freshly check native session and current vehicle membership there. Returned account ID is matched against stored ownership, not accepted from a user method argument. IDs use bounded printable ASCII `[A-Za-z0-9_.:@/-]`, maximum 160 characters; adapt provider identifiers to stable internal account IDs upstream.

- `register(operatorContext, {account, vin, stream, source='telemetry', expires_at, energy_basis='battery_session_counter'})` → `{binding_id, expires_at}`. Operator establishes explicit account+VIN+authenticated stream ownership only after consent/current membership. Expiry must be future UTC and no more than 24h away. Source is `telemetry` or separately permitted `simulation`. Only one active binding per VIN/source/stream. Re-enabling an expired/revoked matching binding requires another operator-authorized call and preserves binding identity; active bindings must first be revoked or expire. Changing its counter basis is rejected. Operators must **not** automatically re-enable an opted-out binding. Deletion high-watermarks carry into newly registered streams.
- `ingest(receiverContext, binding_id, events)` → `{inserted, duplicates, suppressed, durable:true}`. Receiver VIN+stream must match the unrevoked, unexpired operator binding on every batch. Caller cannot supply account routing. `source` and energy measurement basis come only from the binding. Journal commit precedes replay; if replay fails after commit, retry or restart recovers the durable journal. A durable commit is not a finalized trip/charge acknowledgement.
- `list(accountContext, {vin, kind?, limit=30, before?})` → `{records, next_cursor, retention_hours:168, source_policy}`; kind `trip`/`charge`, limit 1…100. Required per-VIN query, account-scoped. `source_policy` is `telemetry_only` or `telemetry_and_simulation`. Summaries omit samples, add `sample_count`. Opaque bounded cursor is scoped to account+VIN+kind, ordered by last observed timestamp and ID descending. This is live pagination, not a snapshot across concurrent changes.
- `detail(accountContext, vin, id)` → record plus `samples`, `revision`, `tag`, `note`, `retention_hours:168`; unauthorized/missing/expired record is 404. No cross-account or cross-VIN lookup fallback.
- `annotate(accountContext, vin, id, {tag,note})` → detail. Tag ≤30 Unicode code points, note ≤500; reject extra keys and unsafe control characters. Updates increment revision. Late samples preserve annotations; a late merge retains unique annotations joined with separators (which may exceed individual edit limits; users can subsequently replace them with validated values).
- `deleteRecord(accountContext, vin, id)` → `{deleted:true}`. Deletes selected observed interval's raw events and matching materialized record, atomically replays affected bindings, and retains a no-location suppression interval for seven days. Does **not** extend suppression by a gap window into adjacent sessions. Suppression is account+VIN+kind scoped across stream re-registration; late points inside that observed interval cannot resurrect it. Points outside its known observed interval cannot be claimed as belonging to the deleted session and may form a new explicitly incomplete interval. Adjacent records retain their own samples; if their start confirmation depended on a deleted boundary sample, replay can honestly downgrade that confirmation to unknown rather than retain deleted evidence.
- `deleteAll(accountContext, vin)` → `{deleted, replay_suppressed_through}`. Erases all records and raw/pending samples for this account+VIN across bindings. Retains only binding ownership, revocation/expiry and event-time high-watermarks plus suppression metadata to prevent old replay. New events later than the deletion watermark can be collected if consent remains enabled. This is history clear, **not** collection opt-out or account deletion; revoke each binding too for opt-out. These tables contain no OAuth tokens. Parent account deletion must compose removal of all account VIN history and revocation, and coordinate with its separate auth account deletion policy; module does not implement an identity-provider deletion hook.
- `revoke(accountContext, binding_id)` → `{revoked:true,history_preserved:true}`. Fresh account/VIN authorization required. Blocks ingestion immediately; advances replay floor through revocation time, so later explicit re-opt-in does not backfill the opted-out interval. Previously captured history remains accessible subject to current authorization and seven-day retention. A receiver identity is not ownership consent forever.
- `exportCSV(accountContext,vin,id)` → BOM-prefixed UTF-8 CSV string. `captureCSV(record)` is the pure formatter, not an authorization boundary. Includes source/kind/event ID, sample timestamps, and repeats observed record facts on every row: `start`, `end`, `first_observed_at`, `last_observed_at`, `start_observed`, `complete`, `end_reason`, `energy_method`, `energy_basis`, `record_revision`, plus units and annotations. These are persisted observations, not a claim of current/live vehicle activity; `in_progress` means no end was observed, not that collection is currently active. Unknown fields export blank with no invented missing-reason labels. Quotes commas/newlines/quotes and neutralizes whitespace-prefixed spreadsheet formulas (`= + - @`). Nulls export empty, never invented zero.
- `prune()` → `{events,records,retention_hours:168}`. `recover()` replays journal; `close()` closes SQLite. These are internal maintenance APIs, not public routes. `replay` and the diagnostic `.db` handle are also internal and must never be exposed to native clients.

## Normalized events / provenance

Every event has durable upstream `id`, `kind` (`trip` or `charge`), `at` (strict valid UTC ISO date/time with seconds and optional 1–3 millisecond digits, `Z`). No future or ≥7-day-old events. IDs are unique within binding across both kinds; exact normalized retries are idempotent, differing contents under an ID reject the entire batch with 409. Same-kind/same-time/different-ID points are rejected as ambiguous. The dispatcher must coalesce sparse fields into one stable normalized event **before journaling**. The store does not silently merge independent same-time upstream messages or backfill stale fields.

Trip fields: `gear` P/D/R/N/null, `latitude` degrees ±90, `longitude` degrees ±180 (both or neither), `speed_kph` 0…400, signed `power_kw` −1000…2000, `battery_percent` 0…100, `odometer_km` 0…10,000,000. Unknowns normalize to null. No location is acquired, geocoded or reconstructed; only provided coordinate pairs are stored.

Charge fields: `charge_state` Charging/Starting/Stopped/Complete/Disconnected/NoPower/unknown; `charger_type` ac/dc/unknown; `battery_percent` 0…100 or null; `energy_added_kwh` absolute monotonically increasing **session counter**, 0…100,000 or null. Missing state/type normalizes to `unknown`. `energy_basis` binding is exactly `battery_session_counter`, `ac_charger_session_counter` or `dc_charger_session_counter`. It describes the measurement boundary, not charger connector type. AC charger-delivered and battery-added energy are not interchangeable and **must never be mixed under one binding**. The upstream adapter must verify the source Tesla field's actual meaning and units. The charger type may be AC while the measurement basis is battery-side. No SOC-to-kWh conversion, guessed charger losses or fabricated billing.

## Record shape and lifecycle

Common JSON: `{id, vin, source, kind, start, end, first_observed_at, last_observed_at, start_observed, end_reason, complete, cost:null, cost_currency:null, revision, tag, note}`. All timestamps are UTC strings or explicitly null. `start` is null unless an adjacent observed parked/disconnected/stopped/etc. state precedes a driving/charging transition with no >120s gap. `first_observed_at` still records the actual first captured active event when start was missed. `end` is null until an observed P or charge terminal state. Trip summaries add `distance_km`, `net_energy_kwh`, `energy_method`; charge summaries add `charger_type`, `energy_added_kwh`, `energy_basis`, `energy_method`. Detail adds normalized `samples` including durable event IDs and timestamps.

D/R begins trip observation; zero speed/N/unknown never confirms parking. P closes a trip. Starting/Charging begins charge observation; Stopped/Complete/Disconnected/NoPower closes it. No inferred end-of-batch or wall-clock timeout completion. A >120s event gap ends the preceding interval with `end_reason:'data_gap'`, null end and `complete:false`; the following active observation starts another incomplete interval. Counter decrease splits an explicit `counter_reset` interval with unknown subsequent start; a counter hidden behind null values cannot produce valid energy. Open sessions survive restart and remain visible as incomplete.

Trip distance uses provided monotonic odometer only, not a guessed map route. Net trip energy is labeled a signed trapezoidal power **estimate**, only across continuously observed supplied power points; never a charge-energy replacement. Charge energy is the difference between first and last provided absolute counters **over the observed interval**, not a claim of full-session energy when start is unknown. Any missing counter yields null rather than zero. A genuine known flat counter delta may be zero. `complete` describes observed start/end continuity, not billing/data-field completeness. Cost is always null; authentic billing integration is unimplemented.

Replay sorts `(at,id)` within each binding/kind. New record IDs are SHA-256 of account/VIN/source/persistent binding/kind/first durable event anchor; overlap reconciliation preserves the existing ID and increments revision only when normalized payload changes. Thus identity is deterministic relative to its persisted binding/anchor and stable over retries/restart/ordinary late samples; fresh databases with independently minted bindings need not have equal IDs. A late bridge merging formerly separated records chooses the lexically smallest existing overlapping ID, merges annotations, and removes superseded IDs. It cannot preserve all IDs for a many-to-one merge. It is not an arrival-independent global Tesla session ID.

## Limits, disk safety and retention

Limits: 500 events / 512 KiB serialized per batch; 20,000 retained events per binding; 1,000 retained binding rows. Capacity rejection is explicit (429) and batch-atomic, with no silent journal eviction. **Real high-rate streams need upstream consented rate selection or a future scaled journal design**; this foundation intentionally does not claim unrestricted Fleet telemetry throughput. Seven-day per-event retention applies equally to completed records and raw pending events. Pruning runs at open/read/ingestion and on explicit `prune`; host must schedule pruning at least hourly even during idle periods. Expired data is physically removed from these SQLite tables using secure_delete, not only hidden by list filters. A record containing any expired sample is dropped; later replay may retain only its incomplete unexpired tail. Seven days is an upper bound on retained event age, not a promise that every crossing session remains whole. No backups, external logs or filesystem snapshots are managed here.

Use a **new dedicated private directory/database**. Directory 0700, DB 0600, SQLite DELETE journal, synchronous FULL, secure_delete. Existing symlink path components (including dangling links) and nonregular DB targets are rejected; a private directory must prevent concurrent hostile path replacement (no claim of race-free safe opening in an attacker-writable parent). Validate application ID/schema before changing existing file/directory modes or schema; foreign/legacy SQLite files are rejected unchanged. New SQLite application ID is 1347309379, version 1. Existing legacy history is never migrated or opened intentionally.

## Still required before real collection

The official Tesla Fleet Telemetry receiver process must terminate Tesla's required mTLS, authenticate the VIN from the real transport, and dispatch only authenticated frames. This module **does not implement mTLS**, official receiver registration/configuration, binary decoding, sparse-field coalescing, unit/counter semantic verification, sequence ID derivation, delivery acknowledgements, current account vehicle-membership discovery, native HTTP routes, scheduler, billing, account erasure orchestration or real-car validation. No `verified:true` HTTP gate substitutes for any of these. An adapter must bind authenticated stream ownership via the trusted operator, issue stable event IDs and normalized measurements, and refuse transport/account/VIN ambiguity before calling this API. No live network, server, credentials or production data was accessed while implementing this local foundation.

`backend/native-capture.test.mjs` uses only deterministic synthetic fixtures and local temporary SQLite files with `node:test`/strict assertions. Parent test runner owns execution; these tests were not executed by the implementing subagent.
