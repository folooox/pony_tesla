# Pony 当前需求 — 登录后一次唤醒与同步（2026-10-24 仓库快照）

本节依据用户525，优先于下文所有历史版本。旧配对方案与不唤醒约束不再适用于本节明确批准的一次唤醒，但其他控车、部署、历史功能仍未开放。

- 目标：PONY 使用现有 Tesla 官方授权登录后，无需再手动逐个读取，看到唤醒/等待在线/读取/结果，并最终看到真实电量、温度等有支持的车况及读取时间。
- 沿用现有账号、Node/SQLite/Tesla 后台，不增加账号、平台服务、导航或配对。交付仍是现有应用候选、隔离模拟器验证及后续用户设备实车验收，不是 TestFlight/App Store。
- 触发仅限新一次官方登录成功；会话恢复、令牌续期、切页、前后台切换、重建视图、重复回调不构成新登录，不重复唤醒。用户当前重新登录的排查可执行本轮批准的一次唤醒，须与并行探测去重。
- 只操作确认属于当前账号的选定车辆。唯一车辆可默认；多车且无明确有效选择时先选择，不批量唤醒，切换车辆隔离旧数据和进行中的回调。
- 每次流程唤醒请求至多一次；网络超时/结果未知不重发。可有限次只读查询等待在线，开发须明确总时限、间隔、次数及取消条件；不做后台常驻或无界轮询。已在线仍不允许多发请求。
- 成功分层：登录成功≠唤醒已发送≠车辆在线≠真实数据已取得。实际读到有效数据并进入当前车辆页面后才显示同步完成；部分字段缺失按未知处理，不填零或演示值。旧快照必须明确上次状态及时间，不冒充当前读数。
- 等待超时、限流、权限不足、网络中断、服务失败、解析失败、无缓存分别用可验证证据提示；无缓存不推断离线，未知状态不推断休眠。停止后可提供只读更新，但不能隐含再次唤醒。
- 退出登录/切换账号/更换车辆须阻止旧结果写入新页面。一次性状态不能靠 View.onAppear 或内存布尔值单独防重复；安全实现由开发决定，不能削弱身份验证/车辆归属检查。
- 用户525批准唤醒和只读车况；用户539已明确接受唤醒所需的整组车辆控制授权，但 Pony 仅使用一次唤醒，不开放其他控制。官方同意仍由用户本人完成，不代表允许代理修改凭据、安装服务、部署重启或付费。若服务器需改，开发先交最小变更、影响及回滚范围，再确认执行。

## 可观察验收与证据
1. 实际客户端的合成接收链路覆盖离线、未知状态、精确无缓存404、未知404、超时、429、解析失败和成功；不能只测核心分类函数。
2. 登录回调重复、切页/回前台、会话恢复、超时都不重复发唤醒；等待有硬上限，取消及迟到响应不污染其他账号/车辆。
3. 隔离模拟器以合成响应检查整个提示与结果显示并交截图，不触碰当前用户预览会话。
4. 真实验证分别记录状态检查、唤醒、在线确认、读取的结果类别，不公开账号/位置/车辆私密响应；无权限或失败直接给具体边界，不反复登录。
5. 最终必须验证 Pony 当前会话→原生接口→真实车况→页面显示；服务器单独成功、编译或合成测试通过均不算实车完成。设备安装、实车验证与模拟器结果分开报告。
